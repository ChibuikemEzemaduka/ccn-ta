# CCN AI Teaching Assistant

An AI-powered teaching assistant for ECSE 4670: Computer Communication Networks.
It gives students 24/7 course-grounded help, guides them through homework without
revealing answers, lets them escalate questions to teaching staff, and gives
instructors tools for ticket management, problem-variant generation, and analytics.

---

## Files NOT in the repository

For security and privacy, several files and folders are deliberately excluded
from version control (see `.gitignore`). They contain secrets, student data, or
large generated content, and they will not be present after you clone the repo.
You must create or generate them manually on the server. The table below lists
every one and how to recreate it.

### Secrets (must be created by hand)

| File | What it is | How to recreate |
|------|-----------|-----------------|
| `.env` | API key + dashboard password | Copy `.env.example` to `.env` and fill in the values (see **Setup** below). |
| `*.key`, `*.pem`, `*.crt`, `*.cer` | TLS certificate and private key for HTTPS | Obtain from your IT department / certificate authority and install into the reverse proxy (nginx). Not part of the app itself. |

### Student & teaching-staff data (created by the app at runtime)

These are created automatically the first time the app writes to them. On a fresh
deployment they simply start empty; you populate them by adding users and by
normal use. Never commit them — they contain personal data.

| File | What it holds | How it gets created |
|------|--------------|--------------------|
| `students.json` | Student roster: names, emails, hashed passwords | Created when you add the first student. |
| `tickets.json` | Escalated questions and their full threads | Created automatically on the first escalation. |
| `student_replies.json` | Staff replies delivered to students | Created automatically on the first reply. |
| `public_board.json` | Approved Q&A shown on the Class Board | Created when the first item is published. |
| `interactions.json` | Chat interaction logs | Created automatically during use. |
| `feedback.json` | Student feedback records | Created automatically during use. |

### Course content & generated indexes (must be added / rebuilt)

| Path | What it is | How to recreate |
|------|-----------|-----------------|
| `materials/` | Course PDFs, slides, transcripts, homework, solutions | Add the course files following the standard naming convention (see Setup, Step 5), or upload them from the Teaching Staff dashboard. |
| `chroma_db/` | Vector index built from the materials | Rebuilt by running the indexing step after materials are in place. Never edited by hand. |
| `knowledge.json`, `solutions.json`, `assignments.json` | Parsed course content used for retrieval and the guardrail | Regenerated by the ingestion/indexing step. |
| `parse_cache.json`, `homework_parse_cache.json` | Ingestion caches to skip unchanged files | Regenerated automatically during indexing. |
| `generated/`, `*.docx`, `*.pptx`, `*.pdf` | Exported variant documents etc. | Produced by the app on demand; not tracked. |

### Environment & caches (rebuilt from the repo)

| Path | What it is | How to recreate |
|------|-----------|-----------------|
| `venv/` | Python virtual environment | Recreate with `python3 -m venv venv` and `pip install -r requirements.txt` (see **Setup, Step 3**). |
| `__pycache__/`, `*.pyc` | Python bytecode cache | Regenerated automatically. |

## Setup (fresh deployment)

### Step 1 — System packages
```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip python3-dev build-essential \
    libxml2-dev libxslt1-dev libjpeg-dev zlib1g-dev libffi-dev \
    git libreoffice poppler-utils tesseract-ocr
```

### Step 2 — Clone the repository
```bash
cd /path/to/deployment          # e.g. /home/<user>/
git clone https://github.com/ChibuikemEzemaduka/ccn-ta ccn-ta
cd ccn-ta
```

### Step 3 — Python environment
```bash
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### Step 4 — Create the `.env` file (secrets)
```bash
cp .env.example .env
nano .env
```
Fill in:
- `OLLAMA_API_KEY` — from https://ollama.com/settings/keys (only needed when using the cloud model).

### Step 5 — Generate admin login details
Run generate_admin_hash.py

### Step 6 — Choose the language model
All model settings live in `llm_client.py`:
- **Cloud (default):** set `USE_CLOUD = True` and provide `OLLAMA_API_KEY` in `.env`. No GPU or local model needed.
- **Local:** set `USE_CLOUD = False`. Requires **Ollama installed on the machine** and the chosen model pulled locally.

### Step 7 — Run the module
For testing:
```bash
streamlit run app.py
```
For production, run it as a `systemd` service (recommended) so it starts on boot
and restarts on failure, behind an nginx reverse proxy that handles HTTPS on
port 443. See the Module Documentation for the service unit and proxy setup.
